# Переход каталога в Supabase

10 ноября 2026. Код подготовлен и проверен, рабочая витрина/Cloudflare ещё не переключены. Основной контракт, импорт 82 карточек и пределы проверки: репозиторий `EasyLim/enka-erp`, `docs/CATALOG.md`.

## Новый источник

GET `https://zilumtvyowzgpwswewtj.supabase.co/rest/v1/rpc/enka_catalog?p_locale=ka|ru|en` с публичным `apikey` из `catalog-backend.json`. Без входа доступны только готовые безопасные проекции текущей публикации. Черновики, авторы, себестоимость и запасы не открываются. Генератор страниц и браузер читают один RPC; кэш отделён от прежнего KV.

Форма отправляет показанную цену как `items[].expected_price`; БД проверяет её под блокировкой публикации. Edge `enka-intake` должен быть обновлён до версии с обработкой `PT409 → 409 catalog_changed`. При конфликте клиент предлагает обновить страницу и подтвердить заказ заново. Старая цена заказа не пересчитывается. Сервер пока допускает старые клиенты без котировки; обязательность включается отдельным шагом после обновления витрины.

Каждая опубликованная карточка содержит `orderable: true`: отсутствие физического остатка не мешает заявке. Для прежнего формата без этого флага сохраняется старое поведение. Скрытые товары не выдаются и не принимаются сервером через ID или SKU.

## Cloudflare

`admin/catalog-api-supabase.mjs` сохраняет GET `/catalog` и `/v1/feed.xml`, читая только Supabase. Записи — 405; сбой Supabase — 503 без подстановки старого KV. `wrangler.catalog-supabase.example.jsonc` — шаблон, не проверенная конфигурация production.

`admin/studio-erp.mjs` перенаправляет вход в ERP и отклоняет старые записи/загрузку/публикацию (410). Экспорт, история и прежний каталог остаются доступны GET за прежней проверкой Access. Класс Durable Object, данные и R2 сохраняются. В действующем конфиге меняется entrypoint после проверки привязок и имени класса; фиктивный шаблон нельзя разворачивать в production.

## Переключение

1. Авторизовать Cloudflare и прочитать действующие конфиги `catalog-api` и всех писателей Studio. Сейчас `wrangler whoami` сообщает об отсутствии входа.
2. Сохранить неопубликованный черновик/переводы Studio, экспорт/историю и текущий опубликованный каталог; остановить прежние записи. Вопрос владельцу о черновике ещё открыт. В публичный снимок неопубликованные данные не входят.
3. Применить проверенную миграцию ERP, обновить Edge/клиент. Повторно сверить 76 исходных SKU и свежесть KA/RU/EN. Импорт создаёт 82 черновика и шесть новых неактивных SKU; первая публикация — отдельное действие.
4. Сравнить анонимную выдачу Supabase с прежним API во всех локалях, цены и постоянные адреса. Публикация меняет учётные цены и указатель атомарно; старые заказы сохраняют снимки.
5. Переключить совместимый Catalog API и Studio, сохранив архив только для чтения. Убедиться, что второго писателя нет; публичные URL фотографий R2 сохраняются.
6. Выполнить полный Jekyll build/проверки, обновить витрину, проверить карточки, список/поиск, формы, адреса, переводы и фид. Тестовый сайт ещё требует отдельной изоляции приёма заявок: вымышленные заказы в production не отправлять.
7. Сверить кэш/свежесть и затем включить обязательность котировки. Откат должен сохранять историю и единственного писателя; возвращение старого пишущего API не является допустимым неявным откатом.

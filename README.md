# ENKA Electronics

Статический магазин на Jekyll с Tailwind CSS. Основная локализация — грузинская.

## Сборка и проверка

Нужны Node.js 22.13+, pnpm 11.25.0, Ruby 4.0.6 и Bundler из `Gemfile.lock`.

```sh
pnpm install --frozen-lockfile
pnpm --dir admin install --frozen-lockfile
bundle install
pnpm check
pnpm build
pnpm check:site
pnpm preview
```

Предпросмотр: `http://127.0.0.1:4173`. Результат сборки находится в `_site/`.
GitHub Actions выполняет полную сборку и проверки перед публикацией. Pull request запускает проверки без публикации. Push в `main`/`master` публикует GitHub Pages; ручной запуск также публикует Cloudflare Pages.

## Панель управления каталогом

Новая ENKA Studio находится в `admin/` и развёртывается отдельно от магазина. Локальный запуск: `node admin/dev.mjs --catalog-file "C:\Users\Nick\Downloads\catalog"`, адрес <http://127.0.0.1:4175/>. Последующие запуски сохраняют черновики. Для облачной версии подготовлены Cloudflare Access, Durable Object, KV и R2; конфигурация по умолчанию предназначена только для отдельного staging.

Пользование, первый вход по коду на почту, команды безопасного тестового развёртывания и план перехода: [admin/README.md](admin/README.md). Корневой workflow проверяет код панели, но не публикует её. Вся папка `admin/` исключена из Jekyll-сборки.

## Главная страница

- `_data/promo_block.yml` — заголовки предложений и `product_id` из каталога. Изображение, название, цена и старая цена берутся из товара, а не из рекламного изображения.
- Баннер предложений переключается вручную: точками, свайпом, перетаскиванием и стрелками клавиатуры.
- `_data/catalog.yml` — категории и подкатегории.
- `_includes/homepage/mini-categories.html` — компактные синие плитки без видимого заголовка. Иллюстрации и фоновые узоры сопоставляются с ID категории, а не с её позицией. `img/categories/objects.webp` — общий оптимизированный спрайт, `img/categories/patterns/` — тематические SVG. Новая категория без иллюстрации использует свою иконку. Обычные ссылки работают без JavaScript; при доступном контроллере нажатие открывает подкатегории.
- `_data/popular_items.yml` — порядок популярных товаров.
- `generate_pages.js` — получает публичный каталог, проверяет данные и создаёт `_products/`. Пустой или некорректный каталог останавливает сборку.
- `assets/js/global/catalog.js` — один общий запрос каталога для главной, поиска и избранного, тайм-аут и кэш на 5 минут. Популярные товары и предложения также присутствуют в готовом HTML.

Недоступность браузерного хранилища не мешает загрузке страницы и подтверждению принятого заказа. Избранное и история просмотров сохраняются только на устройстве посетителя.

### Персональная лента главной

`_includes/homepage/recommendations.html` заменяет отдельные короткие блоки популярного и недавних просмотров на главной автоматически выбранными горизонтальными товарными рядами. На главной нет анкеты, настройки интересов, объяснений под карточками или кнопок обратной связи. Движок собирает тематические ряды из ранжированного каталога: сначала четыре ряда, затем по два при приближении к последнему. Каждый ряд содержит до 8 товаров; число рядов не ограничено. Товар появляется в ленте один раз. Кнопка догрузки доступна с клавиатуры, а в браузерах без IntersectionObserver отображается обычным образом. Баннер предложений над лентой остаётся отдельным редакционным компонентом.

- `assets/js/global/recommendation-engine.js` — независимое ранжирование по содержимому каталога: точные и широкие интересы, новые просмотры и переходы, активный просмотр от 15 секунд, темы посещённых разделов, найденные в поиске товары, текущие избранные и только ID успешно заказанных после включения персонализации товаров. Выбор подкатегории также даёт более слабый интерес к её родительской категории. Сигналы поведения затухают с периодом полураспада 14 дней; повтор одного действия с одним товаром ограничен одним сигналом в сутки. Цена и бренд уточняют сходство внутри подкатегории; маржа, комиссия, рекламный статус и размер скидки не входят в оценку.
- `assets/js/global/personalization.js` — отдельный выбор `enka_personalization_consent_v1`, версия текста `2026-11-10`, время выбора и подтверждение 16+. Он доступен в существующем уведомлении о конфиденциальности: только необходимые, персонализация без рекламы или обе цели. Прежнее согласие только на Meta не включает персонализацию. Без отдельного выбора не собираются события и не читаются избранные для ранжирования. Профиль не передаётся серверу, не содержит контактов, произвольного текста поиска, идентификатора посетителя, геолокации или отпечатка устройства. История заказов и старые `recentIds` не импортируются.
- `assets/js/homepage/recommendations.js` — автоматические ряды по темам и интересам, постепенная загрузка, учёт показов только при видимости минимум половины карточки в течение 1,2 секунды в активной вкладке. Каждый четвёртый ряд может знакомить с новой темой; недавно повторявшиеся показы понижают оценку. Успешно заказанный товар исключается на срок сохранения события. Карточки и навигация каруселей используют общий компонент магазина. До согласия допускается подбор по контексту текущего перехода с товара или категории этого же сайта: `document.referrer` не записывается в профиль, внешние источники и поисковые запросы игнорируются.
- `_includes/personalization-controls.html` и `assets/js/global/personalization-controls.js` — дополнительные параметры и очистка профиля только на `/info/privacy#personalization`. Для получения рекомендаций посетителю не требуется выбирать интересы вручную. До 16 лет поведенческий профиль через этот интерфейс не включается. Отзыв сразу удаляет профиль и отключает сбор, включая другие открытые вкладки. Очистка профиля сохраняет настройку согласия и функциональное избранное; при действующем согласии текущие избранные продолжают участвовать в подборе.

Поведенческие события удаляются из используемого профиля через 90 дней, показы — через 7 дней. Выбранные темы и скрытые товары истекают после 90 дней без обновления профиля; согласие — через 180 дней. Очистка истёкших записей выполняется при обращении к профилю; закрытый браузер не запускает фоновое удаление. Отказ хранилища оставляет работу в памяти страницы. Изменения цены и наличия берутся из общего каталога. При сбое API используется встроенный при сборке каталог с сообщением о проверке цены; без JS остаются HTML-карточки и ссылка на полный каталог.

Оценка движка — эвристическая релевантность, а не обученная вероятность клика. Общая модель поведения покупателей, перенос профиля между устройствами и измерение общего CTR требуют серверной инфраструктуры и отдельного решения о данных/согласиях. Улучшение CTR этим изменением ещё не измерено. Локальное хранение само по себе не устанавливает правовое основание обработки. Законный интерес предусмотрен статьёй 5(1)(i), но требует обоснования; для прямого маркетинга статья 12 предусматривает отдельные требования. В этом изменении сохранён консервативный режим согласия для постоянной истории; переход на другое основание требует отдельной оценки применимости, а не простой замены флага по умолчанию. Использованы минимизация данных, ограничение хранения и немедленный отзыв по [закону Грузии о защите персональных данных](https://matsne.gov.ge/en/document/view/5827307), статьи 4, 5, 7 и 32.

`tests/recommendations.test.cjs` проверяет релевантность точных интересов, затухание, разнообразие и полноту ленты, отсутствие повторов, исключения, независимость от выгоды магазина, отдельное согласие, отзыв, сроки хранения и отказ хранилища.

## Изолированная проверка заказов

Сохраните публичный каталог в `.local/catalog.json`, выполните сборку и запустите:

```sh
node scripts/preview.cjs --mock-services
```

Этот режим подменяет каталог, отправку заказа и отслеживание локальными обработчиками и отключает аналитику. Реальные заказы не отправляются. Номер `555000000` имитирует ошибку сервера; другие корректные номера имитируют успех. Для проверки недоступного каталога добавьте `--catalog-error` и откройте новый origin/порт без кэша каталога.

`pnpm check` проверяет валидацию данных, генерацию страниц, обработку сбоев, защиту заказов и безопасность HTML. `pnpm check:site` проверяет главную и все страницы товаров: локальные ссылки, метаданные, Product JSON-LD, наличие, поля формы, отсутствие повторных скриптов/ID и служебных файлов в публикации.

## Общие компоненты

### Выбор языка

Хедер и футер используют `_includes/language-picker.html`, список `_data/languages.yml`, один `assets/js/global/languages.js`. Три основных варианта — грузинский (оригинал), английский и русский; четвёртый пункт раскрывает остальные языки с поиском по названию на грузинском, русском, английском и родном языке. SVG-флаги хранятся локально в `img/flags/` (flag-icons 7.6.0, MIT; лицензия рядом).

Тексты автоматически переводит Google Translate Element прямо на исходном домене, без API-ключа, платной подписки, проксирования страниц или установленной нами квоты символов. Исходный язык явно задан `ka`; промежуточный ручной перевод и словари отсутствуют. Служебный интерфейс заменён собственным выбором языков с указанием Google Translate. Скрипт Google загружается только после выбора иностранного языка или для восстановления предыдущего выбора. Настройка сохраняется в localStorage и функциональной cookie; отказ localStorage не блокирует страницу. Перевод не меняет URL, товарные `data-*`, обработчики или endpoint заказа. Имя, телефон и код отслеживания в выводе исключены из перевода.

Ограничение: Translate Element — устаревшая интеграция. Google не гарантирует её доступность для новых коммерческих сайтов; это не официальный бессрочный бесплатный API. Блокировщики, ограничения Google или изменения сервиса могут остановить перевод. При ошибке загрузки остаётся исходный сайт и появляется повторная попытка. Поддержка грузинского не гарантирует безошибочный машинный перевод. Документация: https://support.google.com/translate/answer/2534559 .

Шапка подключается из `_includes/header.html`, оформляется Tailwind-классами в этом шаблоне и управляется `assets/js/global/header.js`. На широком экране логотип, каталог, поиск и компактные иконки действий расположены в один ряд. На телефоне поиск всегда доступен во втором ряду; остаётся также окно поиска из нижней навигации. Строка помощи на широком экране уходит при прокрутке, основная шапка закрепляется. Высота измеряется через ResizeObserver, чтобы якоря, фильтры и галерея учитывали загрузку шрифта и масштабирование. На низких экранах шапка прокручивается вместе со страницей. Отдельных библиотек, обработчика прокрутки и размытия в шапке нет.

Общие SVG-иконки используют заливку `currentColor`: геометрия находится в `_data/icons.json`, вывод — `_includes/icons.html`. Иконки категорий, мобильной навигации и динамических карточек также выполнены с заливкой; флаги, логотип и декоративные фоновые узоры сохраняют своё оформление.

Кнопка камеры в поиске открывает `_includes/modals/photo-search.html`. `assets/js/main/photo-search.js` принимает JPG/PNG/WebP до 10 МБ, поддерживает перетаскивание и сравнивает изображение с каталогом по эмбеддингам MobileNet V2. Это базовый поиск по визуальному сходству, без гарантии точной модели товара; фон, ракурс и качество фото влияют на выдачу. Запрос обрабатывается на устройстве: фото не отправляется на сервер, не сохраняется в хранилище браузера, object URL освобождается при закрытии. TensorFlow.js 4.22.0 и MobileNet 2.1.1 с лицензиями лежат в `assets/vendor/photo-search/` и загружаются только после выбора фото; веса модели загружаются из Google Storage. Первый запуск требует подключения к сети и времени для загрузки модели. Ошибка не мешает обычному текстовому поиску.

`scripts/build-photo-index.cjs` готовит `assets/data/photo-search-index.json` во время `generate_pages.js`: Node.js читает публичные фотографии, sharp приводит их к размеру 224×224, а та же версия модели строит нормализованные векторы. Готовый индекс хранится в репозитории, неизменившиеся URL фотографий используют сохранённые векторы. Это обходит ограничение CORS хранилища картинок без прокси и изменения его прав. Новые или изменённые фото попадают в фотопоиск после очередной сборки; цена, доступность и перевод товара берутся из текущего каталога. Удалённые и отсутствующие в индексе товары не показываются. Тесты загрузки файлов и ранжирования находятся в `tests/photo-search.test.cjs`.

`assets/js/main/search.js` использует общую загрузку каталога, задержку ввода 180 мс, до шести подсказок и ссылку на все результаты. Запрос синхронизируется с мобильным окном. Подсказки и страница результатов используют один `matchesCatalogSearch` из `assets/js/global/catalog.js`: название, бренд, SKU, ID, несколько слов и грузинская транслитерация. Поддерживаются стрелки, Escape, Tab, объявления состояния для скринридеров и IME. Уход фокуса, закрытие окна или новый ввод отменяют применение старого ответа; сетевую ошибку можно повторить. Форма в шапке сохраняет обычный GET-переход. Эти сценарии проверяет `tests/search.test.cjs`, единое подключение шапки на всех типах страниц — `scripts/check-site.cjs`.

В подсказках обоих вариантов поиска старая цена показывается зачёркнутой только при действительной скидке. Мобильная панель товара использует плавающий блок с фото, текущей и старой ценой, доставкой, избранным, ссылкой на товар и переходом к форме. На узких экранах вспомогательные действия скрываются, чтобы оставить место цене и покупке. Кнопка покупки скрывается, когда видна кнопка в форме; во время ввода панель не перекрывает форму. Нижнего ряда управления основной галереей нет: остаются миниатюры, свайп, клавиатура и увеличение по нажатию на фото; счётчик объявляется скринридером.

Футер подключается из `_includes/footer.html` и оформляется Tailwind-классами в нём. Карточки создаёт один `assets/js/product/card.js`; серверный вариант `_includes/homepage/product-card.html` использует те же Tailwind-утилиты. Размещение карточек в сетках и каруселях задаётся контейнерами; внешний вид карточки от страницы не зависит.

Хлебные крошки товара, категории и поиска используют `_includes/breadcrumbs.html`, `_includes/breadcrumb-item.html` и `_includes/breadcrumb-separator.html`. Категория обновляет только пункты через `assets/js/global/breadcrumbs.js`, клонируя общий шаблон и иконки. Оформление витрины использует Tailwind 4: все стили компонентов, адаптивные размеры и состояния заданы утилитами непосредственно в HTML/Liquid-шаблонах и создающей разметку JavaScript. Прежние CSS-файлы компонентов и `@apply` удалены. Служебные классы остаются только там, где их используют JavaScript или условные Tailwind-селекторы.

Правки дизайна вносятся в Tailwind-классы соответствующего компонента. Общие утилиты документа (доступность, полосы прокрутки браузера и скрытие служебного интерфейса Google Translate) находятся в `_includes/document-classes.html`; шрифт и цвета — в `@theme` файла `assets/css/input.css`. Обычный CSS остался только для `@font-face` и двух `@keyframes`; спиннеры используют встроенный `animate-spin`. Сборщик сканирует только явно указанные шаблоны и скрипты, браузер получает один `assets/css/style.css`. Отдельные CSS-подключения, `@apply`, CSS-файлы компонентов и блоки `<style>` не добавляются; `check:site` проверяет этот контракт и структуру страниц по стабильным ID и data-атрибутам. JavaScript задаёт вычисляемую геометрию и состояние взаимодействий, но не создаёт таблицы стилей. Админка `admin/` — отдельное приложение и в эту сборку не входит.

### Каталог и результаты поиска

`_pages/category.html` и `_pages/search.html` используют общие компоненты `_includes/listing/` с Tailwind-классами и `assets/js/main/catalog-listing.js`. Контроллеры страниц подключаются только на этих двух страницах. Сохраняются старые ссылки `?kitchen&sub=coffee`, `?category=kitchen` и поисковые параметры `result`, `q`, `search`; новые ссылки используют явные параметры. Посторонние рекламные параметры и якорь сохраняются. Цена задаётся в целых лари: поля используют цифровую клавиатуру и шаг 1, дробные значения фильтра не принимаются. Невалидная сортировка и номера страниц нормализуются.

Фильтры, сортировка и догрузка по 16 товаров сохраняются в URL и восстанавливаются через «Назад»/«Вперёд». Поиск использует те же правила, что подсказки в шапке: бренд, SKU, ID, несколько слов и транслитерация. Сортировка доступна с клавиатуры через нативный select. Мобильное окно цены использует общий контроллер модальных окон: черновик применяется по кнопке, закрытие отменяет изменения, число подходящих товаров обновляется в окне. Выбор одной/двух колонок хранится по возможности; отказ хранилища не мешает работе.

Есть отдельные состояния пустого запроса, пустой категории, отсутствия результатов и ошибки с повторной загрузкой. Без JavaScript каталог показывает все товары сборки с обычными ссылками, поиск предлагает каталог и телефон. Поисковая страница закрыта от индексации и исключена из sitemap. `tests/listing.test.cjs` проверяет маршруты, цены, наличие, сортировку, соответствие подсказкам, повторную загрузку, пагинацию и черновик фильтра; `scripts/check-site.cjs` проверяет готовые страницы, метаданные, labels, ссылки и подключения.

### Модальные окна

Все модальные окна используют общий контроллер `assets/js/global/modals.js` и Tailwind-классы в `_includes/modals/`. Шапка и кнопка закрытия остаются на месте; прокручивается только `.modal-body`. В поиске закреплена также строка ввода. На мобильных учитываются safe area и высота видимой области при открытой клавиатуре. Фотогалерея сохраняет полноэкранный режим. Контроллер отвечает за стек окон, `inert`, Tab/Shift+Tab, Escape, возврат фокуса и позиции страницы, отмену незавершённого закрытия и reduced motion. Закрытие фоном требует нажатия и отпускания на фоне; заполненная форма заказа защищена от случайного касания. Имя и телефон сохраняются в памяти страницы до успешной отправки. Отслеживание отменяет запрос при закрытии и игнорирует устаревшие ответы. Эти сценарии покрыты `tests/modals.test.cjs` и `tests/tracking.test.cjs`.

## Информационные страницы

Все пять страниц `info/` используют `_layouts/info.html`, общие хлебные крошки и Tailwind-классы в шаблоне и разметке страниц. Навигация и реквизиты находятся в `_data/info.yml`. Существующие URL сохранены. FAQ работает без JavaScript; отслеживание использует общее окно и обычную ссылку как запасной путь. Шаблон заявления на возврат — `assets/documents/withdrawal-form.txt`. В условиях возврата приведены ссылки на закон и пояснения GCCA.

`assets/js/global/privacy.js` загружается перед `capi.js`: клиентская рекламная аналитика и её идентификаторы выключены до явного согласия. Выбор на 180 дней можно изменить на странице конфиденциальности; отказ удаляет рекламные cookies и локальные копии, сохраняя историю заказов и защиту от дублей. Старое однокнопочное уведомление не считается согласием. Недоступность хранилища оставляет выбор в памяти текущей страницы. `tests/privacy.test.cjs` проверяет согласие, отзыв, истечение срока, смену выбора в другой вкладке и независимость заказов; `scripts/check-site.cjs` проверяет все пять страниц, метаданные, навигацию, локальные ссылки, якоря и скачивание.

## Страница товара

Цена, наличие, галерея, характеристики, форма и рекомендации присутствуют в готовом HTML. Общий каталог обновляет цену и наличие одновременно в форме, мобильной панели и структурированных данных. При недоступности каталога остаются данные сборки, сообщение о необходимости подтверждения оператором и кнопка повторной загрузки. Удалённый из доступного каталога товар нельзя заказать. Отсутствующий товар, «скоро» и неизвестные статусы показывают ссылку на альтернативы вместо формы.

Заказ подтверждается только после успешного ответа обработчика. Ошибки сети, HTTP и явные ошибки JSON сохраняют введённые данные и позволяют повторить отправку; ожидание ограничено 20 секундами. Прямой и быстрый заказ используют ID товара из каталога, общую защиту от дублей и блокировку параллельной отправки. Аналитика и доступность хранилища не влияют на подтверждение принятого заказа. При отключённом JavaScript доступен заказ по телефону.

Для проверки изменившейся цены, наличия или удалённого товара можно передать локальный каталог: `node scripts/preview.cjs --mock-services --catalog-file .local/catalog-edge.json`. Все сервисы в этом режиме локальные. Галерея поддерживает свайп, кнопки, стрелки клавиатуры, Home/End и увеличение; Escape закрывает окно и возвращает фокус. Видеоплеер загружается с YouTube только после нажатия.
